# 诊断日志与 GitHub 反馈

诊断日志默认关闭，且不记住开启状态：每次启动后都需要手动开启。Lite / Full 使用相同的日志功能，无需安装额外组件。

## 复现并导出

1. 打开“帮助与安全”，开启“记录详细诊断日志”。
2. 重现问题，例如导入 MIDI、切回游戏、开始/暂停演奏或进行音频转谱。开启前发生的问题不会补录。
3. 点击“导出日志 ZIP”，选择保存位置。开启期间也可以导出；关闭记录后，本次运行的日志仍可导出。
4. 自行解压检查内容，再点击“GitHub 反馈”，填写复现步骤，手动附加 ZIP。程序不自动上传任何日志。

日志在 `%LOCALAPPDATA%\GamePianoAutoplay\logs` 中按运行会话保存。没有 `LOCALAPPDATA` 时使用系统临时目录。界面导出只包含本次运行的日志；需要导出时请不要先退出程序。历史日志不会自动上传，可以在退出程序后手动清理该日志目录。

## 记录范围

- 应用版本、Windows / Java 版本、处理器数量、显示器分辨率与缩放比例。
- 前台进程名、PID、窗口句柄、进程查询方式、查询失败的 Win32 错误码；不记录窗口标题原文。
- 演奏配置、音符/批次数量、时间位置、倒计时、暂停/继续、等待游戏前台、停止与完成状态。
- 程序主动发送的钢琴点击坐标、客户区尺寸、按键扫描码以及发送结果。**不会监听或记录用户的全局键盘输入**。
- 音频引擎检查、转谱模式、工作进程输出、退出码、异常堆栈。

不包含 MIDI / 音频文件本体、截图、完整系统环境变量或账号信息。路径、邮箱和常见凭证字段会尽力脱敏；第三方转谱组件的自由文本仍可能含有个人信息，不能保证完全自动脱敏，分享前请自行检查。

## 文件与性能限制

- 后台异步写入，演奏线程不等待文件写入。队列拥堵时跳过日志，导出摘要记录跳过数量。
- 本次运行最多保留 4 个约 2 MiB 的分片，超过后删除最早分片，因此长时间测试可能不再包含最初的事件；建议在复现后及时导出。
- ZIP 包含 `events-*.jsonl`（时间有序事件）、`environment.txt`、`capture-summary.txt` 和反馈说明。
- 不覆盖已有导出文件；文件名冲突时请换一个名称。
- 日志不是防崩溃转储；强制终止、断电或磁盘故障可能丢失尚未写入的事件。
