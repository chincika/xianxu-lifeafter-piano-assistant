# Windows 游戏输入

桌面工作台提供两条受前台保护的输入路由：

- 88 键高保真模式：根据客户区大小计算 A0–C8 坐标，使用鼠标 `SendInput` 依次移动和点击；
- 23 键兼容模式：把映射后的游戏键转换为扫描码并使用键盘 `SendInput`。

88 键模式不会逐音符进行八度折叠。MIDI 21–108 保持原音高，范围外音符直接丢弃。演奏期间系统鼠标会随音符移动。

坐标并不保存为屏幕绝对像素。每个触发批次都会重新读取目标窗口客户区的左上角、宽度和高度，再用 52 白键的标准几何比例计算键位。客户区两个角会通过目标窗口的 Per-Monitor DPI 上下文转换为物理坐标，最后才归一化到 `SendInput` 要求的虚拟桌面坐标，因此支持窗口移动、窗口缩放、多显示器和不同 DPI。

## 为什么使用扫描码

23 个游戏键在 `Piano23Layout` 中保存 Windows Set 1 扫描码。播放时不依赖当前键盘布局把字符重新翻译成虚拟键，而是使用 `KEYEVENTF_SCANCODE` 发送，因此数字、字母和符号键都按物理位置触发。

一个和弦的执行过程是：

```text
检查前台窗口
  -> 一次 SendInput（所有键 DOWN，随后所有键 UP）
```

游戏不支持通过长按延音，因此 MIDI 音符时长不会决定按键保持时间。默认 `--tap-ms=0`，与参考项目的默认点击一样，在一个输入批次内完成按下和松开。若游戏漏键，可以把 `--tap-ms` 调为 5–35ms，此时 DOWN 和 UP 会拆成两批。

## 找到目标窗口

先把游戏切到前台，然后执行：

```powershell
.\gradlew.bat run --args='--inspect-window'
```

程序会打印进程名、PID、窗口标题和 HWND。当前机器上观察到目标游戏进程名为 `lifeafter.exe`。

## 预演和真实播放

推荐直接启动桌面工作台：

```powershell
.\gradlew.bat run
```

选择 MIDI 后，界面会显示音符数、时长、触发批次和折叠数量。点击“开始演奏”后有 3 秒倒计时；在倒计时结束前切回游戏。若目标进程或标题不匹配，程序会失败退出而不是发送按键。

命令行默认只预演：

```powershell
.\gradlew.bat run --args='C:\Music\song.mid G3'
```

显式开启真实输入：

```powershell
.\gradlew.bat run --args='C:\Music\song.mid G3 --play --process=lifeafter.exe --countdown=3 --tap-ms=0'
```

可增加 `--title=明日之后`，使进程名和标题两个条件都必须匹配。标题含空格时，需要遵循 PowerShell/Gradle 的参数引号规则。

## 停止和失败保护

- F8 请求停止，播放等待循环会快速响应；
- Ctrl+C 的关闭钩子会尝试释放仍按下的扫描码；
- 游戏不在前台时不会发送下一批按键；
- `SendInput` 返回部分成功时按失败处理，并立即补发松开事件；
- 正常结束和异常结束都会执行 `releaseAll()`。

没有实现隐藏注入、驱动注入或反作弊绕过。
