# Windows 游戏输入

桌面工作台提供两条受前台保护的输入路由：

- 88 键鼠标模式：根据客户区大小计算 A0–C8 坐标，默认使用不移动系统光标的实验性窗口消息点击，也可切换到鼠标 `SendInput` 移动并点击；
- 23 键兼容模式：把映射后的游戏键转换为扫描码并使用键盘 `SendInput`。

88 键模式不会逐音符进行八度折叠。MIDI 21–108 保持原音高，范围外音符直接丢弃。兼容点击会让系统鼠标随音符移动；实验模式向前台游戏 HWND 投递带客户区坐标的 `WM_LBUTTONDOWN/WM_LBUTTONUP`，不会移动系统光标。`PostMessage` 成功只表示消息进入了窗口队列，不能证明游戏已处理，因此游戏无声音时必须切回兼容点击。

坐标并不保存为屏幕绝对像素。每个触发批次都会重新读取目标窗口客户区的左上角、宽度和高度，再用 52 白键的标准几何比例计算键位。客户区两个角会通过目标窗口的 Per-Monitor DPI 上下文转换为物理坐标：兼容模式继续归一化到 `SendInput` 的虚拟桌面坐标，实验模式则换算回目标窗口客户区坐标，因此两种模式都不会保存固定屏幕像素。

## 为什么使用扫描码

23 个游戏键在 `Piano23Layout` 中保存 Windows Set 1 扫描码。播放时不依赖当前键盘布局把字符重新翻译成虚拟键，而是使用 `KEYEVENTF_SCANCODE` 发送，因此数字、字母和符号键都按物理位置触发。

一个和弦的执行过程是：

```text
检查前台窗口
  -> 一次 SendInput（所有键 DOWN，随后所有键 UP）
```

游戏不支持通过长按延音，因此 MIDI 音符时长不会决定按键保持时间。默认 `--tap-ms=0`，与参考项目的默认点击一样，在一个输入批次内完成按下和松开。若游戏漏键，可以把 `--tap-ms` 调为 5–35ms，此时 DOWN 和 UP 会拆成两批。

## 找到目标窗口

先把游戏切到前台，然后执行：

```powershell
.\gradlew.bat run --args='--inspect-window'
```

程序会打印进程名、PID、窗口标题和 HWND。内置识别名单为 `lifeafter.exe` 和新版客户端的 `mingrizhihou.exe`。默认配置自动兼容两者；手动填写其中任意一个名称时，也会识别另一个名称。其他自定义进程仍按名称精确匹配，`FeverGamesLauncher.exe`、`mrzh_launcher.exe` 等启动器不在名单中。

进程身份通过 Win32 `QueryFullProcessImageName` 以 `PROCESS_QUERY_LIMITED_INFORMATION` 权限读取；读取失败时，按前台窗口的 PID 在 Toolhelp 进程快照中查询可执行文件名。两个途径都失败时保持“未知”，不会把标题相似的其他进程当成目标。设置中的进程名允许省略 `.exe`，也允许粘贴带引号的完整可执行文件路径，进程名和可选标题仍需同时匹配。

界面“等待游戏前台”表示当前前台窗口尚未匹配，不能据此判断游戏是否启动。点击“开始演奏”后在倒计时内切回游戏，或直接在游戏中按 F7。若仍无法匹配，打开“帮助与安全”查看实际前台进程和窗口标题，检查设置中的进程名是否属于游戏本体而非启动器；游戏客户端不同也可能使用不同名称。若游戏以管理员权限运行且识别后仍无法接收输入，再尝试以相同权限启动弦序。识别进程与 Windows 是否允许向其发送输入是两个独立步骤。

## 预演和真实播放

推荐直接启动桌面工作台：

```powershell
.\gradlew.bat run
```

选择 MIDI 后，界面会显示音符数、时长、触发批次、折叠数量和游戏演奏进度。点击“开始演奏”后有 3 秒倒计时；在倒计时结束前切回游戏。若目标进程或标题暂时不匹配，桌面端会进入“切屏等待”而不是发送输入；目标游戏重新回到前台后会从冻结位置自动继续。

命令行默认只预演：

```powershell
.\gradlew.bat run --args='C:\Music\song.mid G3'
```

显式开启真实输入：

```powershell
.\gradlew.bat run --args='C:\Music\song.mid G3 --play --process=lifeafter.exe --countdown=3 --tap-ms=0'
```

88 键窗口消息实验模式：

```powershell
.\gradlew.bat run --args='C:\Music\song.mid G3 --play --process=lifeafter.exe --input=mouse88 --mouse-input=window-message'
```

可增加 `--title=明日之后`，使进程名和标题两个条件都必须匹配。标题含空格时，需要遵循 PowerShell/Gradle 的参数引号规则。

## 停止和失败保护

- F7 在桌面程序已有可演奏乐谱且当前未演奏时启动演奏；
- F9 在暂停与继续之间切换；暂停期间冻结演奏时间轴并释放可能残留的输入；
- F8 请求停止，播放等待循环会快速响应；
- 切换到软件或其他窗口时，桌面端停止发送输入、释放当前按键并冻结时间轴；切回游戏后从同一时间点自动继续，不会批量追赶错过的音符；
- F8 手动停止后保留当前演奏断点，再次开始默认续弹；停止状态下也可以拖动进度条选择新起点；
- Ctrl+C 的关闭钩子会尝试释放仍按下的扫描码；
- 游戏不在前台时不会发送下一批按键；
- `SendInput` 返回部分成功时按失败处理，并立即补发松开事件；
- 窗口消息实验模式只有在 DOWN 与 UP 都成功进入消息队列时才视为发送成功；
- 正常结束和异常结束都会执行 `releaseAll()`。

没有实现驱动注入或反作弊绕过；窗口消息模式只是公开 Win32 消息接口的兼容性实验。
